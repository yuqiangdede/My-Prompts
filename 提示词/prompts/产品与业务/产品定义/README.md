# 产品定义 Prompt 使用说明

本目录用于把一个模糊想法快速整理成可评审的产品方案。

## 包含的 Prompt

- [想法产品化](想法产品化.md)

## 具体能做什么

适合以下任务：

- 把一句产品想法整理成产品定位、目标用户和核心场景。
- 划分 MVP 必做、暂缓和明确不做的范围。
- 梳理业务对象、主要流程、页面清单和验收标准。
- 输出可以继续交给产品经理、设计师或开发团队的方案草稿。

不适合直接代替详细市场调研、真实用户访谈或完整技术设计。

## 示例

### 输入

```text
想做一个面向园区的低功耗设备预警平台。
设备发现人员后上报图片，视频专网人工复核，确认后推送到互联网 APP 处置。
希望先做一个可以现场演示的 MVP。
```

### 预期结果

Prompt 会输出类似内容：

- 一句话产品定位。
- 目标用户与使用场景。
- 设备接入、人工复核、APP 处置的业务闭环。
- MVP 必做功能和不做清单。
- 核心对象，例如设备、事件、录像、处置记录和人员。
- 页面建议，例如预警中心、设备列表、事件详情和 APP 处置页。
- Given-When-Then 验收标准。
- 主要风险、假设和后续路线图。

## 使用方式

1. 打开 [想法产品化.md](想法产品化.md)。
2. 将最后的 `{{产品想法}}`、背景、限制和目标替换为真实内容。
3. 把完整 Prompt 交给模型。
4. 对输出中的“事实”和“假设”分别审核，再进入详细需求设计。
