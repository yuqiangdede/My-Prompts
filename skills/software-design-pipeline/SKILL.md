# software-design-pipeline

## description

将模糊的 B 端或行业系统需求，通过 01–10 的固定顺序转化为可冻结的模块、数据、流程、页面规格和 UI Prompt，并在关键阶段执行质量 Gate。

## input

- 原始业务想法、需求描述或问题陈述。
- 已确认的业务术语、角色、实体、规则和页面信息（如有）。
- 当前步骤所需的上一步确认产物。

## workflow

严格按以下顺序执行，每次只推进一个步骤：

1. `steps/01 问题澄清与反问.md`：问题澄清与反问。
2. `steps/02 问题拆解.md`：问题拆解。
3. `steps/03 需求风险扫描.md`：需求风险扫描，执行 Gate ①。
4. `steps/04 决策与方案对比.md`：决策与方案对比。
5. `steps/05 模块边界审计.md`：模块边界审计。
6. `steps/06 数据模型与状态校验.md`：数据模型与状态校验，执行 Gate ②。
7. `steps/07 关键流程异常枚举.md`：关键流程异常枚举。
8. `steps/08 需求分析与页面规格.md`：需求分析与页面规格。
9. `steps/09 页面-流程-权限一致性校验.md`：页面、流程、权限一致性校验，执行 Gate ③。
10. `steps/10 效果图渲染.md`：效果图渲染。

每一步必须输出确认后的中间产物，供下一步读取。Gate 失败时只能回退到当前步骤规定的步骤；第 10 步只有 Gate ③ 通过后才允许执行。

## rules

- 不得跳步、合并或倒序。
- 当前步骤未确认，不得进入下一步骤。
- 03 不重复 01 已澄清的问题。
- 06 必须先于 07，先稳定状态再枚举异常。
- 09 未通过时，禁止执行 10。
- 任何推测必须显式标记，不得编造业务事实。
- 其余原始提示词和专项模板位于 `references/`，不改变主流程的 Gate 顺序。

## output

- 已确认的需求边界和问题拆解。
- 风险、决策、模块、数据、状态和异常流程结果。
- 页面、流程、权限一致性校验结果。
- 可用于下游 UI 设计和生图的页面规格与 UI Prompt。
- Gate 通过/失败状态及必要的回退位置。

## examples

从一段模糊的行业系统需求开始，先执行 `01 问题澄清与反问.md`，只输出澄清问题；完成确认后进入 `02 问题拆解.md`。在 `03 需求风险扫描.md` 发现阻断级风险时，回退到 `01 问题澄清与反问.md` 或 `02 问题拆解.md`，不得继续生成页面。
