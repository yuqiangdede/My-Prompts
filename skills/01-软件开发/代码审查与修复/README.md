# 代码审查与修复 Skill 使用说明

## 这个 Skill 能做什么

对现有代码、提交或 Pull Request 做影响面分析，找出真实缺陷，按严重程度排序，并在证据充分时直接完成修复和回归验证。

适合接口兼容性、并发问题、空值异常、状态流转错误、资源泄漏和测试缺口。

## 具体例子

### 输入

```text
问题：事件归档任务偶尔重复生成两个 MP4 文件。
项目：Java Spring Boot + MySQL + Redis。
关注代码：ArchiveTaskService、定时任务和事件处置接口。
要求：不能通过简单加全局锁降低全部任务吞吐量。
```

### Skill 会做什么

1. 找到任务创建入口、重试入口和定时扫描入口。
2. 画出同一个事件可能重复进入归档流程的调用链。
3. 检查事务、唯一约束、幂等键和锁的作用范围。
4. 区分根因、次要问题和纯风格问题。
5. 使用唯一索引、条件更新或事件级锁完成最小修复。
6. 增加并发测试和失败重试测试。

### 最终能得到什么

- 按 P0～P3 排序的问题清单。
- 每个问题对应的文件、代码证据和影响。
- 根因修复方案，而不是只在异常处打补丁。
- 实际测试结果和未覆盖风险。

## 使用方式

阅读 [SKILL.md](SKILL.md)，提供仓库、问题现象、复现方法和不允许修改的范围。只有代码风格问题时，不应扩大成架构重构。
