# 图像提示词设计

## description

把模糊的生图想法转化为结构稳定、可迭代、可复用的图像生成指令。适用于写实摄影、电影剧照、UI 概念图、产品图、插画和信息图，不绑定单一模型语法。

## input

- 画面目标与使用场景
- 主体、动作和环境
- 构图或参考图
- 画幅比例与分辨率
- 风格、色彩和光线
- 必须保留与禁止出现的元素
- 是否需要跨图一致性

## workflow

### 01 明确画面任务

先判断图片属于：

- 写实摄影
- 电影叙事
- 产品展示
- UI 或界面概念
- 插画海报
- 信息图或示意图

不同类型使用不同的重点，不能把摄影参数机械套到所有图片。

### 02 锁定主体与叙事

明确：

- 谁或什么是主主体
- 主体正在做什么
- 观众第一眼应看到什么
- 环境与主体是什么关系
- 画面需要传达什么情绪或信息

### 03 设计空间与构图

描述：

- 景别：特写、近景、中景、全景、远景
- 机位：平视、俯视、仰视、侧面、过肩
- 主体位置和视线方向
- 前景、中景、背景
- 留白、对称、引导线、层次和遮挡

涉及参考图时优先锁定空间关系和镜头意图，而不是逐项罗列物体。

### 04 设计视觉控制

按需要选择：

- 光线方向、软硬、时间和反差
- 主色、辅色、点缀色和饱和度
- 材质、纹理和天气
- 镜头焦段、景深、快门感和颗粒
- 风格参考的可观察特征

不要只写“高级感、电影感、震撼”，要写出这些效果对应的视觉特征。

### 05 写约束

明确：

- 必须出现
- 必须保持
- 不得出现
- 不得改变
- 文本、Logo、水印和敏感元素要求

负面约束只保留高价值项目，避免堆数十个泛化负面词。

### 06 生成结构化提示词

推荐顺序：

```text
任务类型 → 主体与动作 → 环境 → 构图与机位 → 光线 → 色彩 → 材质与细节 → 风格 → 画幅 → 约束
```

### 07 迭代

一次只调整一组变量：

- 构图
- 主体
- 光线
- 色彩
- 风格
- 细节密度

记录变化和结果，避免同时改完后无法判断哪个因素有效。

## rules

1. 参考艺术家或作品时优先提炼可观察的视觉特征。
2. 不复制真实演员或普通人的身份特征，除非输入和授权明确。
3. UI 图需要说明信息层级、组件关系和交互状态，不能只描述“科技蓝”。
4. 信息图中的文字准确性应后期排版，不依赖生图模型生成大量文字。
5. 跨帧任务必须固定人物、服装、场景、镜头轴线、色彩和关键道具。
6. 不把模型参数、镜头参数和形容词无差别堆叠。

## output

- 画面拆解
- 主提示词
- 负面约束
- 可替换变量
- 迭代方案
- 跨图一致性控制项

## examples

### 地图设备图例看板

```text
生成一张纯 UI 交互稿，不是业务流程图。画面主体是地图系统右侧的“图例管理看板”，地图底图只作为弱化背景。

看板分为四列：设备、点状要素、线状要素、面状要素。每列包含统一的分类标题、图标预览、名称、显示开关和编辑入口。补齐原图中空缺区域，保持信息密度均衡。

视觉要求：桌面端政企 GIS 产品，清晰克制，浅色背景，卡片层级明确，边框和阴影轻微，间距一致，可直接用于产品评审。16:9 横版，正视图，无透视展示。

禁止：流程箭头、夸张发光、复杂地图细节、无意义装饰、大段错误文字、水印。
```
