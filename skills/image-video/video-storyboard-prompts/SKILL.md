# 视频分镜提示词

## description

将主题、脚本、流程或参考画面转换为可生成、可剪辑、具备镜头连续性的视频分镜提示词。重点控制镜头目的、动作变化、时长、空间关系和跨镜头一致性。

## input

- 视频主题与目标受众
- 总时长和画幅
- 脚本、旁白或业务流程
- 人物、场景和视觉参考
- 视频模型或制作方式
- 必须展示的关键节点
- 是否需要字幕、配音或界面演示

## workflow

### 01 定义视频目标

明确视频要完成哪一种任务：

- 讲清业务流程
- 展示产品功能
- 讲述故事
- 营造氛围
- 演示操作步骤
- 输出宣传短片

### 02 拆分叙事节拍

把内容拆为：

- 建立背景
- 引出问题
- 展示关键动作
- 出现变化或冲突
- 得到结果
- 收束信息

每个节拍只承担一个主要信息目标。

### 03 设计镜头表

每个镜头至少包含：

- 镜头编号
- 时长
- 景别与机位
- 主体和动作
- 环境与时间
- 摄像机运动
- 光线和色彩
- 前后镜头衔接
- 旁白、字幕或音效

### 04 控制动作

视频提示词优先描述可观察的变化：

- 人物从哪里走到哪里
- 设备如何启动或响应
- 界面哪个组件发生什么变化
- 镜头如何推、拉、摇、移或跟随
- 动作开始和结束时的状态

避免在一个短镜头里安排多个互相冲突的动作。

### 05 锁定连续性

跨镜头固定：

- 人物外观、服装和道具
- 场景布局和时间
- 镜头轴线与视线方向
- 设备位置和界面状态
- 色彩、光源和天气

对发生变化的内容单独列出“状态变化”。

### 06 生成单镜头提示词

推荐结构：

```text
镜头目的 → 起始画面 → 主体动作 → 摄像机运动 → 环境变化 → 光线色彩 → 结束状态 → 连续性约束
```

### 07 剪辑检查

检查：

- 信息是否按正确顺序出现
- 镜头时长是否足够理解动作
- 相邻镜头的方向是否跳轴
- 是否缺少动作起点或结果
- 字幕和旁白是否与画面重复

## rules

1. 不把一整段故事塞进一个视频生成提示词。
2. 单镜头优先一个主动作、一个镜头运动。
3. 业务流程视频必须保证箭头、网络边界和责任主体准确。
4. UI 演示优先使用后期合成保证文字与交互准确。
5. 不依赖模型自动维持人物和道具一致性，必须显式锁定。
6. 无叙事意义的镜头不保留。

## output

- 视频结构
- 分镜表
- 每镜头生成提示词
- 连续性控制表
- 旁白与字幕建议
- 剪辑与转场说明

## examples

### 三网录像归档流程短片

```text
制作 45 秒横版技术说明视频，讲清“设备接入网产生录像、视频专网按需研判并归档、互联网 APP 临时查看”的流程。

镜头必须依次展示：
1. 低功耗设备产生事件并在设备接入网保存录像；
2. 视频专网发起临时研判请求；
3. 文件录像通过 FTP 摆渡，流式录像通过 NCG 回放；
4. 人工确认预警后创建归档任务并保存 90 天；
5. APP 按需申请，录像摆渡到互联网临时存储并在 1 天内清理。

每个镜头只展示一个跨网动作。三张网络区域的位置、名称和颜色全片固定，箭头方向必须准确。不要生成大段文字，关键名称使用后期字幕。
```
