# 结构化长文写作

## description

将资料、观点和目标转化为结构清晰、事实可靠、适合特定读者的长文。采用提纲、证据、初稿、批评和修订的多阶段流程，而不是一次生成全文。

## input

- 写作主题
- 目标读者和发布场景
- 核心观点或预期结论
- 事实、素材和必须引用的来源
- 篇幅、语气和格式
- 禁止出现的内容

## workflow

### 01 明确写作任务

确认：

- 读者看完要理解什么
- 读者要做出什么判断或行动
- 文章必须回答哪些问题
- 哪些事实不能写错

### 02 整理素材

把素材拆为：

- 已确认事实
- 作者观点
- 案例与数据
- 引用材料
- 尚需核实的信息

对缺失但关键的信息先检索或明确留空，不用想象补齐。

### 03 生成提纲

提纲需要体现论证关系：

1. 问题或背景
2. 核心判断
3. 支撑证据
4. 反方或限制
5. 建议或结论

每节写明目的和需要使用的证据，避免只有标题没有逻辑。

### 04 撰写初稿

要求：

- 每段只承担一个主要作用。
- 事实与观点明确区分。
- 标题层级稳定。
- 术语首次出现时解释。
- 重要结论前给出依据。

### 05 批评检查

从以下维度审查：

- 是否真正回答主题
- 是否存在逻辑跳跃
- 是否重复、空泛或堆术语
- 数据和引用是否准确
- 是否忽略关键反例
- 开头和结尾是否有实际信息

### 06 修订与压缩

删除：

- 无证据的绝对化表达
- 同义重复
- 不影响结论的背景堆积
- 模板化套话

补充：

- 必要定义
- 关键过渡
- 风险和适用边界
- 可执行动作

## rules

1. 不为了显得专业而堆砌术语。
2. 不虚构数字、案例、人物和来源。
3. 不把未经证实的观点包装为行业共识。
4. 不机械使用“首先、其次、最后”。
5. 引用内容应服务于论证，而不是装饰。
6. 有明确读者时，优先使用读者熟悉的语言和例子。

## output

- 写作定位
- 结构化提纲
- 完整文章
- 事实核验清单
- 可选标题与摘要

## examples

### 技术方案说明

```text
面向项目经理和开发人员，写一篇“低功耗设备事件录像跨网归档方案”。

文章需要说明：
- 设备接入网、视频专网和互联网的职责；
- PIR 文件录像与 DE 球 SD 卡录像的差异；
- 临时研判、确认预警、归档和 APP 查看流程；
- 文件目录、任务幂等、失败重试和定时清理；
- 当前未确认的现场条件。

先产出提纲并检查流程闭环，再写正文。不要虚构接口字段和性能参数。
```
