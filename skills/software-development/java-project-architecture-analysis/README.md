# Java 项目架构分析 Skill 使用说明

## 这个 Skill 能做什么

帮助开发人员快速接手一个现有 Java 项目，说明系统如何启动、模块如何依赖、请求如何流转、数据如何变化，以及主要风险在哪里。

适合 Spring Boot、Spring Cloud、Maven/Gradle 多模块和遗留系统。

## 具体例子

### 输入

```text
项目：视频预警平台后端
技术栈：Spring Boot、MyBatis、MySQL、Redis、Kafka
目标：分析事件从设备上报到 APP 处置的完整链路，后续要增加录像归档功能。
重点：状态机、事务边界、消息可靠性和跨网接口。
```

### Skill 会做什么

1. 确认 JDK、构建方式、启动类、配置和模块结构。
2. 找到事件接收 Controller、Service、Mapper、消息生产者和消费者。
3. 画出设备上报、智能复核、人工确认、APP 推送和归档的调用链。
4. 梳理事件状态、数据库表、事务边界和异步消息。
5. 标出循环依赖、跨层调用、重复模型和高风险耦合。
6. 给出分阶段改造路线，而不是直接推倒重写。

### 最终能得到什么

- 项目地图和模块职责表。
- 核心调用链、数据流和状态机。
- 外部系统与中间件依赖清单。
- P0～P3 风险列表。
- 可执行的扩展或重构建议。

## 使用方式

从 [SKILL.md](SKILL.md) 开始。最好同时提供仓库、运行环境、关注业务和允许执行的构建命令。分析结论必须引用实际文件和配置，不能只根据目录名称判断。
