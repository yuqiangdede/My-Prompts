# Codex 任务执行 Skill

## 这个 Skill 做什么

让**当前 Codex** 在现有代码仓库里真正完成一次明确的软件开发任务：

```text
读取仓库
→ 定位真实实现与调用链
→ 修改文件
→ 补测试
→ 执行测试/构建
→ 修复失败
→ 汇报可核验结果
```

适合新增功能、修复 Bug、补测试、调整配置和小范围重构。

## 不做什么

它不再负责“生成一条给另一个 Codex 的提示词”。如果你的目标是先整理一份任务书，再复制给其他编码 Agent，使用：

`prompts/software-development/codex-task-brief.md`

## 例子

用户：

```text
项目：Spring Boot 事件管理系统
任务：给事件驳回接口增加驳回原因，旧客户端不传该字段时仍要兼容。
限制：不能修改事件表主键和现有状态枚举；允许新增数据库字段。
验收：接口测试通过，旧请求不报错，新请求校验原因长度。

直接在当前仓库修改并验证。
```

Skill 应执行：

1. 阅读 README/AGENTS.md、构建文件和相关代码。
2. 定位 Controller、DTO、Service、状态流转、数据模型和测试。
3. 确定最小修改范围后直接实施。
4. 补兼容逻辑、校验与回归测试。
5. 实际运行可用的格式检查、测试和构建。
6. 验证失败则继续修复，除非遇到明确外部阻塞。
7. 最终汇报真实修改文件、命令结果、未验证项和剩余风险。

## 最终得到什么

- 实际代码/配置/测试变更。
- 实际执行过的验证结果。
- 兼容性与影响说明。
- 外部阻塞或未验证项。

不会把“建议怎么改”或“给 Codex 的任务提示词”当作任务完成。
