# Panorama Generation — 场景/参考图直达 360° 交互网页

## 核心目标与触发

当用户说“把这个场景做成 3D 页面”“参考这张图生成可旋转的全景”“描述一个房间/街道/森林然后生成网页”时，直接执行本 Skill。**生成全景图是默认内置步骤，而不是需要用户自己准备的前提。**

接受三种入口，均产出同一种交付：

| 入口 | 用户提供 | 自动执行 |
| --- | --- | --- |
| A. 文字场景（默认） | 一句话或详细描述 | 场景规划 → 生图 → 全景校验 → Three.js 网页 |
| B. 参考图 | 普通照片、概念图、设计效果图（可附描述） | 提取视觉锚点 → 补齐合理的环视场景 → 生图 → 校验 → 网页 |
| C. 已有全景 | 真正的 360° equirectangular 图片 | 校验 → 网页（不重复生图） |

缺失天气、时间、风格等非必要信息时合理默认，不要把确认细节变成阻塞。默认单场景、固定视点、用户可原地环视及缩放。只有用户明确要求时才升级为多场景切换、热点或可行走的真实 3D。

## 必须交付

能调用生图工具、创建文件的环境下，**直接完成实际文件**，不要只返回 Prompt 或代码片段：

```text
output/<scene-name>/
├── index.html          # 真正可运行的 Three.js 交互页面
├── panorama.jpg        # 真正生成/接收的 360° 等距柱状全景；也可用 .png 并同步修改页面路径
└── README.md           # 场景说明、启动方式、资产状态、验证结论
```

使用本 Skill 的 `templates/index.html` 作为可靠的查看器起点；根据场景改标题/默认朝向/必要交互，不要每次从零拼凑缺乏错误处理的示例。`scripts/check_panorama.py` 提供资产尺寸和边界检查。

**重要概念边界：** 球面全景属于可以旋转视角、缩放的 **3DoF 沉浸式 3D WebGL 页面**，不是可自由走动的 6DoF 几何 3D 重建。不要把一张全景图称为带真实几何结构的 3D 模型；如果用户要求在空间中行走、从任意位置观察，请增加真实几何/深度重建方案并说明额外素材与局限。

## 执行步骤

### 01 自动识别输入与工作模式

1. **已有全景：** 判断是否真的是 360° 等距柱状图，不能仅凭“宽图”或 2:1 比例认定合格；未验证时先视为候选资产。
2. **单张参考图：** 通常只有有限视野。以原图的主体、材质、构图、色调、光照为锚点，按合理空间关系扩展其不可见的背面、左右、天顶与地面最低点。**不要把普通照片直接拉宽、镜像、平铺成假全景。** 参考图不存在的背后细节是合理想象，不能保证真实还原。
3. **纯文字：** 自动规划空间类型、360° 环境布局、固定相机位置及可见要素，优先执行生图。
4. **多参考图：** 若出现矛盾，优先用户明确指示；能组合的作为不同方向的外观参考，保持同一时空与相机。

无需用户提供全景图、Three.js 代码或现成网页。可把相机高度默认为约 1.6m（室内/街景）；鸟瞰、室外空中场景按需求调整。

### 02 生成图像：本 Skill 的默认必经步骤

**只要运行环境拥有可用图像生成能力，就必须实际调用该能力并落盘图片，不要停留在“请复制下面 Prompt 自己生图”。**

推荐优先调用支持**参考图/图像编辑**的生图工具处理入口 B；入口 A 用文生图工具。若当前图像模型本身支持原生 360° 等距柱状投影，直接请求输出 2:1 图像（建议 4096×2048，受限时至少 2048×1024）；输出文件与实际生成尺寸必须一致，禁止把普通图像简单缩放成 2:1 冒充全景。

生图提示词应组合：

- **场景主描述：** 用户的主体/建筑/环境/季节/风格/光照，参考图的关键纹理、颜色与视觉识别点。
- **空间一致性：** 一台相机位于唯一固定中心点，环视 360°，所有方向的尺度、地形、道路、墙面、家具、天空和阴影逻辑一致，禁止跨方向重复关键主体。
- **投影硬约束：** `360-degree full spherical equirectangular panorama, 2:1 aspect ratio, 360° horizontal × 180° vertical, single centered camera viewpoint, straight level horizon near vertical midpoint, seamless horizontal wrap, coherent zenith and nadir`。
- **负面约束：** `no fisheye circle, no cubemap cross, no split panels, no collage, no perspective-only wide-angle photo, no duplicated objects, no broken horizon, no visible seam, no text, no watermark, no UI`。

应同时用中文讲清楚：画面左右两端接壤；中心视角不出现孤立的“画框”；头顶与脚下必须有连续场景，不得留黑。不要依赖提示词中写了“360”就宣称生成图是正确的全景投影。

**如果模型不支持原生 2:1/球面全景：**

1. 首选切换到具备全景生成/编辑/拼接能力的可用工具；
2. 可采用固定相机中心的多方向视图（前/右/后/左/上/下）→ 一致性校验 → 按标准球面投影重映射或拼接，必要时修接缝；
3. 多视图合成必须保持共用相机位置、曝光、光照、主体关系和投影，不能把六张独立生成的照片粗暴横向拼接或只改变图片比例；
4. 如无法获得合格 360° 纹理，必须明确「全景生成未完成」，提供待补资产和严格 Prompt；可以生成带占位说明的网页，但不能宣称“从描述生成了完整 3D 页面”。

如发现接缝、极点或重复主体问题，允许重生/修复有限次数（建议 1–3 次），优先修复局部而不是无止境地重复生成。

### 03 保存并验证真实全景资产（Gate ①）

输出目标必须是实际存在、浏览器可加载的图片文件，文件名与网页引用严格一致，推荐 `panorama.jpg` / `panorama.png`。

基础条件：

- 宽高约为 2:1，建议 4096×2048，最低建议 2048×1024；实际生成受限时记录分辨率，不伪造。
- 水平 360°、垂直从天顶至地面最低点（180°）；单一视点、地平线接近图像纵向中点。
- 左右边缘物体/墙体/地形/光照连续；天顶和脚下没有明显黑洞、漩涡或重复纹理。
- 没有透视广角伪装、镜像拼接、同一建筑在不合理方位重复出现、文字/水印/UI。

先执行（若 Pillow 不存在则安装或进行人工/其他方式检查）：

```bash
python scripts/check_panorama.py output/<scene-name>/panorama.jpg
```

脚本只负责**机器可检**的宽高、分辨率和接缝像素差异提醒；像素统计通过并**不能证明**投影正确。必须进一步在球面网页里目视检查左右接缝、抬头/低头、地平线、运动方向。若工具只做宽高检查而未做视觉检查，状态应标注“格式通过，360° 视觉未验收”。

### 04 从全景图创建网页（Gate ②）

先复制 `templates/index.html` 到交付目录（或按同等质量生成），按照实际资产后缀修改 `DEFAULT_PANORAMA`，并调整页面标题。该模板提供：

- Three.js 球体内表面映射 2:1 全景纹理，正确设置 sRGB 色彩空间；
- 鼠标拖拽环视，滚轮缩放；手机单指旋转、双指缩放；
- 复位视角、全屏切换、本地图片选择和拖放替换；
- 错误提示（WebGL 不支持、Three.js CDN 无法加载、图像不存在、比例错误）；
- 移动端响应式界面、高分辨率纹理保护与合理 FOV 限制。

默认只有**原地环视**，不要增加看似可行走但实际只是旋转天空球的虚假导航。如有多张全景照片且用户要求，可以增加热点场景跳转；若要求测量空间尺寸、遮挡深度、走动视差，应使用显式 3D 几何/深度数据。

不要为了基本查看器开发后端。默认示例固定 Three.js 版本并通过 CDN 引入；若目标为无外网/内网离线，必须下载对应版本的模块到 `vendor/`，调整 import 位置，并将其随成品一并交付。**CDN 版不应声称完全离线可运行。**

### 05 实测与交付

优先在交付目录启动静态服务：

```bash
cd output/<scene-name>
python -m http.server 8000
# 浏览器访问 http://localhost:8000
```

有可用浏览器/截图工具时实际打开并检查：

1. 进入页面后全景资产真实加载（不是占位图或纯黑屏）。
2. 鼠标/触摸环视及 FOV 缩放正常，转动方向自然。
3. 左右循环边界无明显缝隙，天顶/脚下正常。
4. 重置、全屏和本地选图生效；页面缩放/窗口改变后布局正常。
5. 断网/缺失全景文件时给出可理解的提示；移动端尺寸与显存压力可接受。

能运行自动化浏览器就做实际检查；缺少浏览器/WebGL 能力时必须写清楚“静态文件已生成，交互未在当前环境实测”。不要把静态代码审阅称为运行通过。

## 一键调用示例

- `用 panorama-generation 生成一个雨夜东京街道的 360° 沉浸网页，霓虹灯和湿地倒影，直接交付 index.html 和全景图。`
- `把我上传的这张客厅照片当作风格和前方视角参考，补齐四周场景，直接做成手机能滑动的 3D 全景网页。`
- `这是我的 panorama.png，不要重新生图，直接给它做一个支持触屏、缩放和全屏的 Three.js 页面。`

## 严格规则

1. **输入可以只有场景描述或普通参考图**，不得把用户上传 360° 图片设为前置条件。
2. 当前能生图就直接调用工具生成**真实**纹理文件；不应把“可复制 Prompt + 空白模板”包装成完整交付。
3. 输入单图时，原图未展示的区域是生成式推断，不保证物理/建筑细节真实，不得声称精准还原整栋空间。
4. 禁止用 2:1 拉伸、复制、左右镜像来伪造真实全景。
5. 纹理必须和页面一起交付并使用正确相对路径；不要依赖第三方短期临时图片 URL。
6. 若任何关键步骤实际失败，明确指出阻塞及已完成部分，不得隐瞒或虚构通过测试。
7. 用户说“3D”而未指定可走动时，默认提供 360° 沉浸式 WebGL 页面，并正确说明它是 3DoF；用户明确要求走动时不得以球面全景替代。

## 最终反馈格式

简要交代：**输入模式、实际生成的全景资产及尺寸、网页文件路径/下载方式、运行方法、Gate ① 与 Gate ② 检查状态、仍存在的问题**。可执行的环境要优先交付文件，而不是长篇讨论实现方案。
