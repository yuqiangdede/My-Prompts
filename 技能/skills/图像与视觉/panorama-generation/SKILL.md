# Panorama Generation

## 目标

完成一个可交付的 360° 全景查看方案，而不是只输出两个互不关联的 Prompt。

最终至少应得到：

- 一张符合 2:1 equirectangular 规范的全景资产，或在当前环境无法直接生图时得到可直接用于生图工具的严格 Prompt 与明确待补资产位。
- 一个可直接运行的 `index.html` Three.js 查看器。
- 对投影、接缝、方向、交互和性能的检查结果。

## 输入

- 场景描述
- 时间/天气
- 相机高度（默认约 1.6m）
- 视觉风格
- 全景图片来源：已有图片 / 当前环境生成 / 待外部生成
- 目标运行环境：本地双击、本地 HTTP、内网页面等

## workflow

### 01 明确资产状态

判断：

1. 用户是否已经提供全景图。
2. 已有图片是否为 2:1 equirectangular。
3. 当前环境是否具备图像生成能力。

不要把普通广角、鱼眼圆图或立方体展开图当成等距柱状全景图。

### 02 生成或准备全景资产

如果当前环境能够生成图片，直接生成并保存资产；如果不能，输出严格的全景生成 Prompt，并为查看器预留明确文件名，例如 `panorama.jpg`。

资产规范：

- 2:1 宽高比，如 4096×2048。
- 水平覆盖 360°，垂直覆盖天顶到地面最低点。
- 地平线水平且接近垂直中线。
- 左右边缘无缝衔接。
- 单一固定机位，避免重复主体、断裂道路、空间冲突。
- 天顶和地面最低点避免黑洞、旋涡、严重拉伸。
- 不在全景图中生成 UI、Logo、水印或大量文字。

### Gate ① 全景资产可用

进入查看器实现前，至少确认：

- 文件路径/预期文件名明确。
- 投影格式明确为 equirectangular。
- 如果已存在真实文件，检查尺寸与宽高比。
- 如果资产尚未生成，明确标注为外部阻塞，不声称已经完成视觉验收。

### 03 创建 Three.js 查看器

生成可直接运行的 `index.html`，至少支持：

- 球体内表面或等效方式正确映射 equirectangular 纹理。
- 鼠标拖拽旋转。
- 滚轮缩放。
- 移动端单指拖动和双指缩放。
- 全屏、重置视角、本地图片选择。
- 加载状态、图片失败和 WebGL 不可用提示。
- 合理限制俯仰角和 FOV，避免视角翻转。
- 响应式布局。
- 明确 Three.js 版本；如使用 CDN，同时说明如何切换为本地依赖。

不要开发后端。

### 04 本地运行验证

能运行命令时，优先使用本地 HTTP 服务验证，而不是只凭静态阅读判断：

```text
python -m http.server 8000
```

或使用项目已有静态服务器。

检查：

- 页面能加载。
- 纹理实际显示。
- 左右方向没有明显反转。
- 接缝位置合理。
- 拖拽/缩放/重置有效。
- 图片加载失败时有明确错误状态。

### Gate ② 交互查看器可用

只有实际运行过的项目才能标记为“已验证”。如果当前环境无法打开浏览器/WebGL，明确写“代码已生成，交互未在当前环境验证”。

### 05 性能与兼容性检查

关注：

- 超大纹理与 GPU 最大纹理尺寸。
- 移动端内存和解码压力。
- CDN/离线网络依赖。
- 本地 `file://` 与 HTTP 的行为差异。
- 图片方向错误时的水平旋转修正方式。

## rules

1. 不把普通广角照片伪装成 360° 全景图。
2. 不在没有真实资产时声称接缝、天顶或最低点已经通过视觉验收。
3. 查看器必须引用明确的全景文件路径，并提供加载失败处理。
4. 不依赖后端服务完成基本查看。
5. 可以生成文件就直接生成，不只给代码片段。
6. 真实验证与“理论上可运行”必须明确区分。

## output

- 全景资产状态（已生成 / 已提供 / 待外部生成）
- 全景图生成 Prompt（仅在需要时）
- `index.html`
- 建议目录结构
- 本地运行命令
- Gate ①/② 状态
- 已验证项、未验证项和兼容性风险
